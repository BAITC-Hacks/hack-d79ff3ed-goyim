# Контракт AI-заполнения формы

Задача: AI event-request parser. Один исполнитель, существующие Python/HTML/CSS/JS, без новых зависимостей.

`POST /api/parse-event`, JSON `{ "text": "описание мероприятия" }`, максимум 1000 символов.
Модель возвращает строго пять полей: `city`, `date`, `format`, `category`, `budget`. Каждое может быть `null`.
HTTP 200: `{ "fields": { ... } }`. HTTP 400/422: `{ "error": "русское пояснение" }`.
Отсутствие ключа, тайм-аут или сбой API: HTTP 503 и
`AI-помощник сейчас недоступен. Заполните параметры вручную.`

Существующий `event_format` означает тип события: свадьба, той, корпоратив, конференция, юбилей, день рождения.
`format` у парсера может содержать этот тип или явно указанный способ участия: офлайн, онлайн, гибрид.
При наличии способа участия он показывается в редактируемом дополнительном поле, не передаётся в поиск и не фильтрует каталог.
Тип события в этом случае берётся локально из однозначного слова в исходном запросе, иначе поле остаётся пустым.
Например, «офлайн-свадьба» → `format=офлайн`, существующий фильтр `event_format=свадьба`.

Год 2026 является явно показанным контекстом календаря. «5 октября» означает 2026-10-05.
Если нет дня или месяца, дата — null. Неизвестные или неоднозначные параметры — null.
Неизвестные AI поля очищаются в форме, а не подменяются прежними значениями.
После заполнения всех обязательных полей и проверки валидности формы кнопка AI автоматически вызывает существующий `/api/recommend` ровно один раз.
Если данных не хватает или форма невалидна, поиск не выполняется: пользователь видит подсказку, дополняет поля и нажимает существующую кнопку подбора.
Ошибка API и поздний ответ после пользовательских изменений не запускают поиск. Поля остаются редактируемыми, ручной поиск сохраняется.
Изменения пользователя во время запроса не затираются поздним AI-ответом.

В AI передаются только текст текущего запроса, календарный контекст и имена допустимых значений полей.
Профили, описания подрядчиков, исходный код и история не передаются.
Ввод с распознаваемыми секретами, контактами, идентификаторами или кодом отклоняется локально.
Общая функция `validate_shareable_text` применяется также перед внешним вызовом помощника объяснений: проверяются пожелания и фрагменты выбранных профилей. При срабатывании проверки внешний вызов пропускается, а готовая локальная выдача сохраняется с русским уведомлением. Проверка эвристическая, не гарантирует распознавание любых конфиденциальных данных.
Ключ берётся из `os.environ["OPENAI_API_KEY"]`, не логируется и не возвращается клиенту.

`matcher.py`, формула оценки, ограничения, каталог и существующий `/api/recommend` сохраняются.
В карточках показывается `relevance × 100%` с округлением до одного десятичного знака. Это текстовое соответствие формату и пожеланиям, а не вероятность успеха или доля выполненных обязательных фильтров. Все показанные карточки уже прошли эти фильтры. AI не вычисляет проценты; API, оценки и порядок карточек не меняются.

## Восстановление поиска

Используются существующие `suggested_min_budget`, `alternative_dates` и `rejections`. Нового расчёта подходящих кандидатов нет.
Доплата равна `suggested_min_budget - query.budget`; подсказка применяется только нажатием кнопки и меняет один параметр исходного запроса.
Если пользователь уже изменил форму, старая подсказка не применяется — нужно повторить поиск. Формат участия не меняется и не предлагается как способ изменить выдачу.
Пока выполняется поиск, кнопки подсказок заблокированы. `no_category` не получает бюджетных или календарных альтернатив.

## Сравнение — контракт представления

После существующего отбора сервер добавляет только выбранным карточкам `event_formats` (копия списка из каталога) и `experience_excerpt` (буквальный фрагмент с явным упоминанием опыта/стажа, либо `null`).
Это дополнение представления: `matcher.py`, число карточек, `relevance`, порядок и параметры запроса не меняются. Новых AI-вызовов нет.
Клиент выбирает от двух до трёх уникальных ID из текущих результатов и отображает таблицу. Новая выдача очищает выбор. Отсутствующие данные показываются как «Не указано»; опыт помечается как утверждение профиля.
