# Firebird Match

Подбор до трёх event-подрядчиков с конкретным объяснением каждого выбора.
Решение кейса «Умный подбор подрядчиков» (#79-lite), HackAlem AI, трек «Креативные индустрии».

Заказчик указывает условия мероприятия и получает короткую подборку из каталога.
Каждая карточка объясняет совпадение по условиям и показывает характерный факт из описания подрядчика.

## Быстрый запуск

Нужен **Python 3.10 или новее**. Сторонние библиотеки, npm, база данных и API-ключ для базового режима не нужны.

```bash
python app.py
```

Откройте **http://127.0.0.1:8000**. Остановка сервера — `Ctrl+C`.

На Windows можно дважды нажать `start.bat` или выполнить:

```powershell
py -3 app.py --open
```

На macOS и Linux:

```bash
python3 app.py --open
```

Если порт занят: `python app.py --port 8001`. Все команды выполняются из папки проекта, где лежит `app.py`.
Если Python не установлен, установите Python 3.10+ с [python.org](https://www.python.org/downloads/).

## Что реализовано

- Обязательные поля: город, дата, формат, категория, бюджет в тенге.
- Дополнительные поля: язык, длительность, текст пожеланий до 600 символов.
- Строгая проверка занятости, бюджета, формата, языка и длительности до ранжирования.
- Не более трёх карточек: имя, категории, город, цена «от», объяснение и описание источника.
- Фиксированный порядок карточек при одинаковом запросе и каталоге.
- Раздельные состояния: `matched`, `no_category`, `no_matches`.
- Объяснение короткой выдачи и пустого результата с количествами причин отказа.
- Сравнение с предыдущим запросом при смене только даты: кто стал занят, кто появился или уступил место в первой тройке.
- Предложения соседних дат в пределах ±7 дней, если на них больше вариантов при тех же условиях.
- Подсказка минимального бюджета, если изменение только бюджета даст хотя бы один вариант.
- Явные отметки синтетических профилей, проставленных городов и цен.
- Адаптивный интерфейс на русском и пять демонстрационных запросов.
- Опциональный OpenAI API для выбора факта, на котором акцентируется объяснение.
- Автоматические проверки фильтров, календарей, порядка, пустых результатов, API и отказоустойчивости AI.

Бронирование, отправка заявок и сообщения подрядчикам не выполняются.

## Пользовательский сценарий

1. Открыть приложение. Сразу загружается пример с ведущими в Алматы.
2. Изменить город, дату, формат, категорию и бюджет. При необходимости раскрыть дополнительные условия.
3. Нажать «Подобрать подрядчиков».
4. Сравнить до трёх карточек, объяснения и цитаты из профилей.
5. Посмотреть причины исключения других кандидатов или сравнить соседнюю дату.

Пожелания влияют только на порядок прошедших проверку профилей. Приложение не снимает ограничения автоматически.

## Как работает решение

### 1. Загрузка данных

`data/contractors.csv` — точная копия предоставленного организаторами CSV, переименованная для удобного пути.
В файле 66 профилей, 17 категорий; категории могут пересекаться у одного профиля.
Города: Алматы — 50 профилей, Астана — 15, Зарубежье — 1.
13 профилей помечены организаторами как синтетические; своих профилей мы не добавляли.

Поля со списками разделяются символом `|`, логические поля преобразуются из `True`/`False`, цены становятся числами.
При загрузке проверяются уникальность ID и границы дат занятости.

### 2. Проверка условий

Сначала выбираются город и категория. Если таких профилей нет, возвращается `no_category`.
Затем для каждого профиля проверяются:

- дата отсутствует в `busy_dates`;
- `price_from_kzt <= budget`;
- формат входит в `event_formats`;
- запрошенный язык входит в `languages`, если язык задан;
- запрошенная длительность не больше `max_hours`, если оба значения заданы.

Пустое `max_hours` означает отсутствие привязки к часам присутствия, а не нулевую длительность.
Банкетные залы и другие площадки проходят тот же календарный фильтр, что и люди.
Даты вне **23.09.2026–31.12.2026** отклоняются: занятость за пределами календаря неизвестна.
За основу фильтров берутся структурированные поля; текст описания не отменяет ограничения.

Причины отказа считаются независимо: один профиль может одновременно не пройти по бюджету и дате.
Сумма причин поэтому может быть больше количества исключённых профилей.

### 3. Детерминированное ранжирование

Используется небольшая лексическая TF-IDF эвристика, реализованная средствами Python:

1. Слова приводятся к нижнему регистру, `ё` заменяется на `е`, удаляются короткие слова и стоп-слова.
2. Сохраняются первые 5 символов слова как грубое приближение общей основы. Это **не** полноценная морфология.
3. Считается TF-IDF: `tf * (log((1 + N) / (1 + df)) + 1)`, затем L2-нормализация и косинусная близость.
4. Для формата используется фиксированный словарь связанных слов в `FORMAT_TERMS` (например, корпоратив → деловой, бизнес, форум, компания, тимбилдинг).
5. Без пожеланий оценка равна сходству с форматом. С пожеланиями: `0.75 * сходство с пожеланиями + 0.25 * сходство с форматом`.
6. Сортировка: оценка, округлённая до 8 знаков, по убыванию; начальная цена по возрастанию; ID по возрастанию.

Это оценка текстового соответствия, **не** вероятность успеха и **не** рейтинг качества подрядчика.
Модель не участвует в расчёте порядка, поэтому её недоступность и вариативность не меняют выдачу.

### 4. Объяснения без добавления новых фактов

Первое предложение собирается из проверенных полей: дата, формат, цена и бюджет, при наличии — язык и длительность.
Второе показывает фрагмент описания, явно отмеченный как цитата из профиля.
Длинные фрагменты обрезаются с многоточием. Фрагменты выбираются по близости к запросу и простым признакам конкретики; приветствия получают штраф.

Если подключён OpenAI, модель выбирает **только индекс существующего фрагмента** для каждого из уже выбранных профилей.
Она не генерирует произвольные утверждения, не добавляет подрядчиков и не меняет порядок.
Сервер проверяет ID, число результатов, отсутствие дублей и границы индексов.
При любой ошибке сохраняются локальные объяснения и показывается уведомление.

## Технологии и архитектура

| Компонент | Реализация |
|---|---|
| Сервер и API | Python 3.10+, стандартный `http.server.ThreadingHTTPServer` |
| Данные | CSV, стандартный модуль `csv`, хранение в памяти |
| Ранжирование | Локальная TF-IDF эвристика, без обучения модели |
| Интерфейс | HTML, CSS, JavaScript, Fetch API |
| Опциональный AI | OpenAI Responses API, Structured Outputs |
| Модель по умолчанию | `gpt-4.1-mini-2025-04-14`, заменяется через `OPENAI_MODEL` |
| Проверки | `unittest`, без установки пакетов |

Браузер отправляет JSON в `POST /api/recommend`. `matcher.py` проверяет параметры, фильтрует, сортирует и формирует объяснения.
`ai.py` при наличии ключа уточняет выбор цитат. `app.py` возвращает JSON, а `web/app.js` отображает карточки и причины отказа.

Структура:

```text
app.py                 HTTP-сервер, валидация HTTP-запросов, загрузка .env
matcher.py             каталог, фильтры, ранжирование, объяснения
ai.py                  необязательный выбор фрагментов через OpenAI
data/contractors.csv    исходные 66 профилей
web/                   интерфейс и значок приложения
tests/test_matcher.py   автоматические проверки
.env.example           пример конфигурации без ключа
start.bat              запуск на Windows
```

## Подключение OpenAI — необязательно

1. Скопировать `.env.example` в `.env` в корне проекта.
2. Вписать свой OpenAI API-ключ после `OPENAI_API_KEY=`.
3. Перезапустить `python app.py`.

Ключ читается только сервером, не передаётся браузеру и исключён из Git через `.gitignore`.
Переменные окружения имеют приоритет над `.env`. Содержимое `.env` не отдаётся HTTP-сервером.
Не загружайте `.env` вручную через интерфейс GitHub: при таком способе `.gitignore` не защищает файл.

В API отправляются параметры заказа и фрагменты описаний максимум трёх анонимизированных профилей.
В запросе указан `store: false`. Запросы к OpenAI расходуют API-кредиты.
Сервер ждёт AI не более 4 секунд и затем возвращает локальный результат. Повторные успешные ответы кэшируются в памяти до 128 запросов.
Кэш сбрасывается при перезапуске. Порядок карточек стабилен и без кэша, но выбор цитаты AI после перезапуска может отличаться.

Формат интеграции сверялся с официальной документацией:
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs),
[GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini).

**В этой сборке живой запрос к OpenAI не проверен: ключ не предоставлялся.**
Успех, неправильный ответ и ошибка сети проверены с подставными ответами в тестах.
В локальном режиме приложение работает без сети. В интерфейсе этот режим не обозначается как результат AI.

## Как проверить жюри

В примерах язык и длительность не заданы, пожелания пустые.

| Сценарий | Параметры | Ожидаемый результат |
|---|---|---|
| Плотная категория | Алматы, 15.10.2026, корпоратив, Ведущий, 1 000 000 ₸ | 6 проходят, показаны 3: Буллма, Кики, Мицури Канроджи |
| Изменение даты | Тот же запрос на 16.10.2026 | 4 проходят, показаны Буллма, Куррапика, Мицури Канроджи; Кики занят |
| Редкая категория | Алматы, 15.10.2026, свадьба, Флорист, 500 000 ₸ | 2 карточки; объяснено, что в городе всего 2 профиля категории |
| Не проходит бюджет | Алматы, 15.10.2026, корпоратив, Ведущий, 10 000 ₸ | `no_matches`, причины отказа и предложение бюджета |
| Нет категории | Астана, 15.10.2026, корпоратив, Декоратор, 3 000 000 ₸ | `no_category`, предложение сменить город |
| Площадка | Алматы, 14.11.2026, свадьба, Банкетный зал, 6 000 000 ₸ | 2 карточки: Иноскэ Хашибира и Гохан; занятые исключены |

Пять кнопок примеров заполняют форму и выполняют запрос. Для второго сценария нажмите «Сравнить со следующим днём» после первого.
Повторный подбор с теми же параметрами должен сохранить порядок.

Автоматические проверки:

```bash
python -m unittest discover -s tests -v
```

На момент подготовки проходят **16 тестов**. Среди них проверка всех возвращаемых карточек на 15 датах для ведущих, флористов и банкетных залов с заданными языком и длительностью.
Локальное ядро на контрольном запросе выполнялось за единицы миллисекунд в среде разработки; это не гарантия времени на любом устройстве и не замер живого OpenAI API.
Визуальную проверку в браузере в среде подготовки выполнить не удалось. Перед защитой откройте страницу у себя и пройдите кнопки примеров.

## API

- `GET /api/health` — состояние сервера и количество профилей.
- `GET /api/catalog` — допустимые значения полей, календарь и наличие конфигурации AI (без ключа).
- `POST /api/recommend` — подбор. Заголовок `Content-Type: application/json` обязателен.

Пример тела запроса:

```json
{
  "city": "Алматы",
  "date": "2026-10-15",
  "event_format": "корпоратив",
  "category": "Ведущий",
  "budget": 1000000,
  "language": null,
  "hours": null,
  "brief": ""
}
```

Ответ включает `status`, `cards`, `counts`, `rejections`, `alternative_dates`, `suggested_min_budget`, `explanation_mode` и `elapsed_ms`.
Неверные параметры дают HTTP 400 с объяснением; пустая корректная выдача — HTTP 200 с соответствующим статусом.

## Ограничения

- Только предоставленные 66 профилей и календарь на 100 дней; изменения реальной занятости не синхронизируются.
- Начальная цена не является подтверждённой сметой. Занятость проверяется по датасету, а не по живому календарю подрядчика.
- 8 городов и 18 цен проставлены при подготовке датасета; это показано в карточках, но фильтры всё равно используют эти значения.
- Содержимое описаний — заявления из каталога, а не независимо проверенные достижения. Имена вымышлены.
- Лексическое ранжирование ограничено совпадением основ слов и небольшим словарём форматов, не понимает все синонимы и отрицания. Пожелания не считаются строгими условиями.
- Если описание противоречит структурированным полям, фильтры опираются на поля, а цитата отображается как текст источника.
- Нет регистрации, реальных контактов, бронирования, оплаты и сохранения истории между перезапусками страницы.
- Стандартный HTTP-сервер предназначен для локального демо, а не публичного промышленного размещения. Нет аутентификации или ограничений расходов на API для публичного сервиса.
- Реальный вызов OpenAI требует ключа, сети, доступной модели и кредитов; при сбое остаётся локальный режим.

## Короткий сценарий защиты

1. Показать первый пример и объяснить разные цитаты у трёх карточек.
2. Повторить запрос: порядок не изменился.
3. Сравнить следующий день: Кики занят, появился Куррапика.
4. Показать флористов: всего два, включая явно помеченный синтетический профиль.
5. Показать маленький бюджет и отсутствующую категорию: разные причины пустого результата.
6. Объяснить архитектуру: строгие фильтры → фиксированное ранжирование → фактические объяснения, AI выбирает цитату и не управляет ограничениями.
